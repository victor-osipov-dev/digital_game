# Платформенный слой (`src/platform/`)

Единый интерфейс игры ко всем браузерным площадкам. Игра вызывает только
`platform` из `src/platform/index.ts` и никогда не обращается к SDK
площадок напрямую.

## Провайдеры

| Площадка | Файл | SDK | Статус |
|---|---|---|---|
| Яндекс Игры | `yandex.ts` | `/sdk.js` → фолбэк `https://yandex.ru/games/sdk/v2` | Полная интеграция |
| GamePush | `gamepush.ts` | сниппет `game-score.js` в `index.html` (только `--mode gamepush`) | Интеграция, нужен проект и поле `wins` |
| CrazyGames | `crazygames.ts` | `https://sdk.crazygames.com/crazygames-sdk-v2.js` (тег в `index.html`) | Полная интеграция |
| GameDistribution | `gamedistribution.ts` | `https://html5.api.gamedistribution.com/main.min.js` (грузится сам) | Интеграция, нужен `gameId` |
| Свой сайт / прочие | `noop.ts` | — | Игра работает без рекламы |

## Варианты сборки

Цель выбирается режимом Vite и подставляется в код константой
`__DG_PLATFORM_TARGET__` (см. `define` в `vite.config.ts`):

| Команда | Площадка | Папка вывода | Назначение |
|---|---|---|---|
| `npm run build` | `auto` (детект в рантайме) | `dist/` | Архив для Яндекс Игр |
| `npm run build:yandex` | принудительно Яндекс | `dist/` | Явная сборка под Яндекс |
| `npm run build:site` | `standalone` | `dist-site/` | Свой сайт, без функций Яндекса |
| `npm run build:gamepush` | `gamepush` | `dist-gamepush/` | Публикация через GamePush |

В режиме `standalone` площадка фиксируется на «свой сайт»: Яндекс-провайдер
не создаётся, `/sdk.js` не запрашивается, и вся Яндекс-специфичная
разметка (вход через Yandex ID, таблица Яндекс Игр, подсказки про
сохранение прогресса) скрыта. Обычная сборка (`auto`) не меняется и
по-прежнему годится для архива на Яндекс.

В режиме `gamepush` в `index.html` перед `</body>` вставляется сниппет
GamePush (`window.onGPInit`, загрузчик `game-score.js`), а площадка
фиксируется на `gamepush`. Сниппет, `projectId` и `publicToken` лежат в
`vite.config.ts`; их можно переопределить переменными окружения
`GP_PROJECT_ID` и `GP_PUBLIC_TOKEN`. В обычной и site-сборке сниппета нет.

### Настройка проекта GamePush

1. Добавить домен игры в **Allowed Origins** панели GamePush (иначе SDK
   считает источник недоверенным). Для локальной проверки — `localhost`
   и `127.0.0.1`.
2. В разделе **Players** создать числовое поле `wins` (number, public) —
   по нему строится таблица GamePush. Без поля игра работает, но витрина
   GamePush в лобби покажет ошибку; серверный рейтинг остаётся основным.
   Таблицу можно создать и вручную (**Leaderboards**): игра ищет её по ID
   `101345` или тегу `wins` через scoped-API. Глобальная `global@wins`
   поддерживается как резерв.
3. В настройках рекламы включить fullscreen/interstitial, rewarded и
   sticky-баннер. Игра показывает interstitial только в логических паузах
   (конец партии, выход в меню), rewarded — только по нажатию «Подск.»,
   sticky — в меню/лобби и скрывает его во время партии.
4. Проверить на домене: `[platform] id=gamepush`, `window.__dgGP` заполнен,
   в консоли нет ошибок SDK. Проверка на черновике GamePush — через их
   панель/хостинг.

Что делает провайдер GamePush:

- `gp.gameStart()` после первого кадра, `gameplayStart/Stop` вокруг партии;
- `gp.ads.showFullscreen()` и `showRewardedVideo()` с таймаутами;
- `gp.ads.showSticky()/closeSticky()` для баннера в меню;
- `gp.player.ready`, профиль, `gp.player.login()` по явному нажатию;
- `gp.leaderboard.fetchScoped({ id: 101345 })` (резерв — тег `wins`,
  затем глобальный `fetch({ orderBy: ['wins'] })`); рекорд scoped-таблицы
  публикуется через `gp.leaderboard.publishRecord(...)`, а `wins` для
  глобальной таблицы — через `gp.player.set(...)` + `gp.player.sync()`;
- `gp.fullscreen`, `gp.language`, `gp.isMobile`, события `pause/resume`;
- `gp.gameStart()` — аналог Game Ready; `LoadingAPI` у GamePush нет.

Осознанное ограничение: вход GamePush не создаёт отдельный аккаунт на
игровом сервере. Сетевые партии, как и раньше, используют серверный
гостевой вход (имя в форме), а профиль GamePush нужен для платформенной
таблицы и рекламы. Серверный рейтинг остаётся источником истины: в
`wins` уходит только подтверждённое сервером число побед.

## Что уже покрыто из требований Яндекс Игр

- П. 1.1, 1.19 — SDK инициализируется (`YaGames.init`), `LoadingAPI.ready()`
  вызывается после первого кадра, геймплей размечен `GameplayAPI.start/stop`.
- П. 1.2 — регистрация не требуется: офлайн и сетевой режим доступны
  гостем. На Яндексе в онлайн-лобби можно добровольно войти через Yandex ID;
  это привязывает серверный профиль к ID Яндекса и открывает таблицу Яндекса.
- П. 1.3, 4.7 — звука в игре нет; `gameplayStop` вызывается при сворачивании,
  blur и по платформенным событиям `game_api_pause`/`game_api_resume`
  (они же покрывают автоматический стартовый interstitial Яндекса).
- П. 1.6.1/1.6.2 — полноэкранный canvas + ResizeObserver, жесты, нет
  системного плеера/выделения (user-select отключён).
- П. 1.9 — прогресс (настройки/статистика) сохраняется в localStorage сразу.
- П. 1.10 — нет браузерного скролла, resize/поворот пересобирают layout.
- П. 1.12, 4.1–4.7 — interstitial в логических паузах (конец партии →
  «Заново»/«В меню», выход из комнаты), rewarded — только по явному
  согласию (подсказка; на кнопке — значок «Реклама»). Пауза игры и
  `gameplayStop` — до показа, `gameplayStart` — после.
- П. 1.18 — нет абсолютных URL на CDN; SDK грузится с `/sdk.js`.
- П. 1.21, 1.22 — архив `dist/index.zip`: `index.html` в корне, имена
  ASCII без пробелов, вес ~1.5 МБ при лимите 100 МБ.
- П. 2.2 — правила («Как играть») есть в игре и в меню.
- П. 2.14 — автоопределение языка: `environment.i18n.lang` → дефолт для
  первого запуска (ru/en); ручная смена в настройках приоритетнее.
- П. 6.7 — кнопка «Выход» (`window.close`) скрыта внутри iframe/площадок.

## Дополнительные функции SDK (используются)

- **Полноэкранный режим** — `ysdk.screen.fullscreen` (`status`/`request`/
  `exit`); кнопка «На весь экран» в главном меню. Вне площадки — браузерный
  Fullscreen API (там же, где площадка своего API не даёт).
- **Sticky-баннер** — `ysdk.adv.showBannerAdv()/hideBannerAdv()`: баннер
  показывается в меню/лобби и скрывается во время партии, чтобы не мешать
  игре. Работает, только если в Консоли включена опция «Использовать API
  для показа sticky-баннера»; иначе методы безопасно ничего не делают.
- **Оценка игры** — `ysdk.feedback.canReview()` + `requestReview()`:
  кнопка «Оценить игру» в меню, появляется только если оценка доступна
  этому игроку (нужна авторизация на Яндексе).
- **Ярлык на рабочий стол** — `ysdk.shortcut.canShowPrompt()` +
  `showPrompt()`: кнопка в меню, если ярлык доступен.
- **Буфер обмена** — `ysdk.clipboard.writeText()`: кнопка «Скопировать код»
  в лобби комнаты (с браузерным фолбэком).
- **Yandex ID** — `getPlayer()` вызывается без диалога для проверки уже
  авторизованного профиля; `auth.openAuthDialog()` открывается только после
  явного нажатия. Гостевой выбор использует lite-ID и не открывает диалог.
  Серверный вход — `auth.ya`.
- **Лидерборд Яндекс Игр** — `leaderboards.getEntries/setScore`, ID `wins`.
  Показан отдельным блоком от серверного топа; после онлайн-победы в SDK
  уходит `wins` из `board.list`, а не очки, вычисленные клиентом.

**Ограничение доверия:** текущий `auth.ya` отправляет на сервер UID, который
получен в клиентском SDK; сервер не проверяет подписанный Яндексом токен.
Поэтому это привязка удобного игрового профиля, но не криптографически
подтверждённая авторизация. Серверный рейтинг всё равно нельзя накрутить
клиентским числом побед, однако перед хранением чувствительных данных или
ценной прогрессии нужно добавить серверную проверку официального токена.
- **`game_api_pause` / `game_api_resume`** — подписка через `ysdk.on()`,
  согласована с `GameplayAPI`.

## Осознанно НЕ используем

- Облачные игровые сейвы (п. 1.11 не применяется) — локальные настройки
  хранятся в `localStorage`; вход через Yandex ID сам по себе их не синхронизирует.
- Инап-покупки (п. 1.4, 1.13 не применяются) — покупок в игре нет.
- Автоматическую авторизацию — диалог Yandex ID только по явному действию.
- Асинхронный мультиплеер площадки — используется свой игровой сервер.
  Серверный лидерборд — общий и авторитетный; таблица Яндекса — отдельная
  витрина для Яндекс-площадки, куда копируются проверенные серверные победы.
- Серверное время (`serverTime`) — таймерных наград/событий в игре нет.
- `HISTORY_BACK`/`EXIT` — события только для ТВ-версии, игра управляется
  указателем.

## Ручной чек-лист перед отправкой на Яндекс

1. В консоли: платформы (desktop/mobile), ориентация, возрастной рейтинг,
   жанр, «Как играть», иконка/обложка/скриншоты.
2. Реклама: включить sticky-баннер и опцию «Использовать API для показа
   sticky-баннера» (тогда игра сама прячет его во время партии).
3. Создать в консоли Яндекс Игр лидерборд с ID `wins` (числовой счёт,
   больше — лучше), иначе блок Яндекса покажет ошибку; серверная таблица
   при этом продолжит работать.
4. Вкладка «Инап-покупки» пустая (покупок в игре нет).
5. Опция cloud-saves ВЫКЛЮЧЕНА (настройки остаются локальными).
6. Проверить в черновике: вход через Yandex ID, отказ/гостевой вариант,
   отображение обеих таблиц и запись серверных побед в `wins`.
7. Реклама: interstitial — конец партии; rewarded — подсказка.
8. Проверка с `?debug-mode=16`: индикатор лоадера `IT`, `Initialized`,
   GameReady/Start/Stop в консоли.
9. Модерация 3–5 дней; игра не обновлялась >100 дней → перечитать требования.

## Как добавить новую площадку (например, Poki)

1. Создать `src/platform/<id>.ts` с классом `implements PlatformAPI`
   либо наследником `BasePlatform` (браузерные fullscreen/буфер обмена,
   всё остальное — no-op; все вызовы SDK — в try/catch).
2. Добавить id в `PlatformId` (`types.ts`) и ветку в `createProvider`
   (`index.ts`), детект — в `detect.ts`.
3. Добавить тесты детекта в `tests/platform.test.ts`.
4. Дописать строку в таблицу выше и чек-лист подключения SDK.

Переопределение площадки вручную: `?platform=yandex|gamepush|crazygames|gamedistribution|standalone`.
GameDistribution дополнительно: `?gamedist_id=ВАШ_ID`.
В сборке `--mode site` цель `standalone` жёсткая: `?platform=` её не переопределяет.
В сборке `--mode gamepush` цель `gamepush` тоже жёсткая.

## Как проверить рекламу локально

Важно: `--dev-mode` у `sdk-dev-proxy` — это режим **без соединения
с платформой** (`/sdk.js` подменяется dev-адаптером
`yandex-dev-adapter.js`, игра открывается top-level). Настоящих
рекламных показов там нет по дизайну Яндекса — это не баг игры.

Варианты проверки:

0. **Без прокси, на моке SDK:** `node tools/mock-sdk-server.mjs` — отдаёт
   собранный `dist` и подменяет `/sdk.js` на мок Яндекс SDK (Yandex ID,
   лидерборд, fullscreen, оценка, ярлык, буфер обмена, sticky-баннер,
   видимая «реклама»).
   Открыть `http://localhost:4177/`. Это НЕ настоящий SDK: реклама рисуется
   собственным оверлеем, показов нет — только проверка интеграции.
1. **Флоу без настоящей рекламы (рекомендуется для разработки):**
   `?platform=yandex&fakeads=1` — показы симулируются **видимым**
   оверлеем с обратным отсчётом (interstitial ~2с, rewarded ~3с),
   весь флоу игры проверяется end-to-end. Параметр работает только
   если указан явно.
2. **Настоящие тестовые показы:** запустить прокси **без**
   `--dev-mode`, с `--app-id` черновика, и открыть игру через URL вида
   `https://yandex.ru/games/app/<APP_ID>/?draft=true&game_url=<localUrl>`
   (прокси сам подскажет URL). Реклама идёт с реальной платформы.
3. В консоли будет одна info-строка `[platform] id=...` — видно,
   какая площадка определилась и какой язык взят по умолчанию.
